# 02 · Configuration (environment variables)

All configuration is via **environment variables**. There is no settings file.

## How env loading works

At import time `app.py:26` defines `load_local_env(".env")` and calls it (`app.py:46`). It reads
`.env` line by line and, for each `KEY=VALUE`, sets `os.environ[KEY]` **only if the key is
missing _or_ currently empty** (`app.py:40`). It strips surrounding quotes from the value.

> **Gotcha:** a *blank* assignment in `.env` (e.g. `RABBITMQ_USER=`) still creates the key with an
> empty string. Because `os.getenv("RABBITMQ_USER", "guest")` returns the empty string when the
> key exists, a blank line **overrides** the code's built-in default with `""` rather than
> falling back to it. The code defaults below only apply when the key is entirely absent from the
> environment. Fill the RabbitMQ/S3/API-key fields in `.env`; don't leave them as bare `KEY=`.

`gmaps.py` and `codetails.py` each load `.env` independently (`codetails.load_local_env()`;
`gmaps` uses `python-dotenv`'s `load_dotenv()`).

Helper readers in `app.py`: `_get_bool_env` (truthy = `1/true/yes/on`, `app.py:202`),
`_get_int_env` (`app.py:192`), `_get_float_env` (`app.py:182`). Bare `os.getenv(name, default)`
is used for strings.

## B. Variables in `.env.example` that NOTHING reads (legacy / aspirational)

These keys appear in `.env.example` but are **not referenced by any Python file** in the repo.
They are leftovers from an earlier browser-crawl/proxy/Redis design. Setting them has no effect.

| Key(s) | Was for |
|--------|---------|
| `OUTPUT_PREFIX` | Custom S3 prefix (code hard-codes `single_ra_isi`). |
| `ENABLE_ADDRESS_FALLBACK` | An address fallback toggle (only `ENABLE_INDUSTRY_FALLBACK` is actually read). |
| `BROWSER_POOL_SIZE`, `USER_AGENT` | Headless-browser crawling (no Playwright in the code). |
| `MASSIVE_USER`, `MASSIVE_PASS`, `MASSIVE_PROXY_HOST`, `MASSIVE_PROXY_PORT`, `MASSIVE_MONTHLY_REQUESTS_OFFSET`, `MASSIVE_TIER1/2/3_USD_PER_1000`, `MASSIVE_TIER1/2/3_LIMIT_REQUESTS` | "Massive" residential-proxy tiered pricing. `massive_proxy_cost_usd` is hard-coded `0.0`. |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB`, `REDIS_PASSWORD` | Redis state (the code uses `/tmp` + S3 instead). |
| `SEARCH_FETCH_ATTEMPTS`, `SEARCH_FETCH_CONNECT_TIMEOUT_SEC`, `SEARCH_FETCH_READ_TIMEOUT_SEC`, `SEARCH_FETCH_POOL_TIMEOUT_SEC` | Old per-fetch retry/timeout knobs (only `SEARCH_FETCH_CONCURRENCY` survives). |

> When configuring a deployment, ignore section B and focus on section A.

## C. Minimum viable configuration

To run end-to-end you need at least:

```ini
SERPWOW_API_KEY=<key>
GEMINI_API_KEY=<key>
RABBITMQ_HOST=...      # + PORT/USER/PASS/VHOST as needed
S3_BUCKET=...          # optional; omit to stay local-only under /tmp
AWS_ACCESS_KEY_ID=...  # if S3_BUCKET is set
AWS_SECRET_ACCESS_KEY=...
ENABLE_GEMINI_BATCH_POSTPROCESS=true   # if you want bilingual descriptions
```

Everything else has a working default.
