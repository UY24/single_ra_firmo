# 03 · Data models & schemas

This documents every data shape the service uses: Pydantic request/response models, the queue
job payload, the `state.json` and `output.json` schemas, the per-row `result.context` tree, the
CSV input formats, the XLSX export columns, and the S3 layout.

---

### `CrawlResponse` (`app.py:97`)
The response of every per-row pipeline. `crawl_response.model_dump()` becomes the `result`/`output`
object stored on each row. Fields:

| Field | Type | Meaning |
|-------|------|---------|
| `company_name` | `str` | Echoes the **original** input name (not the transliterated one). |
| `country` | `str` | |
| `firm_id` | `str?` | |
| `input_industry` | `str?` | Industry as provided in input. |
| `input_full_address` | `str?` | Address as provided in input. |
| `official_website` | `str?` | The resolved URL, or `null`. |
| `summary` | `str` | Human-readable status sentence (or, after batch, the company summary). |
| `address` | `str?` | Firmographic address. |
| `phone` | `str?` | |
| `email` | `str?` | |
| `industry` | `str?` | Firmographic industry. |
| `products` | `list[str]` | default `[]` |
| `services` | `list[str]` | default `[]` |
| `website_company_descirption_ai` | `str?` | Country-language description (brief's `Website_Company_Descirption_AI`). Populated by the **batch** step. |
| `website_company_descirption_translated_ai` | `str?` | English description (brief's `Website_Company_Descirption_Translated_AI`). |
| `massive_proxy_cost_usd` | `float` | Per-row **conditional** proxy/page-load cost — designed to be nonzero only when a URL had to be fetched through the Massive proxy. The current codebase has no proxy/page-fetch path, so every assignment is the literal `0.0` (`app.py` sites 2526/2613/2667/2785/3465/3551/3746). |
| `serpwow_cost_usd` | `float` | `serpwow_request_count × SERPWOW_USD_PER_REQUEST`. |
| `gemini_cost_usd` | `float` | Sum of all per-row Gemini call costs (+ batch cost, added later). |
| `total_cost_usd` | `float` | `serpwow + gemini`. |
| `context` | `dict` | Full diagnostic tree — see §5. |

> **Spelling:** the misspelled keys `website_company_descirption_ai` and
> `…_descirption_translated_ai` ("Descirption") come straight from the brief and are used
> consistently across prompts, the result object, and the XLSX columns. Do **not** "fix" them or
> downstream mapping breaks.

## 3. `state.json` — the authoritative per-upload record

Created by `_create_upload_with_rows` (`app.py:6365`), mutated by `update_row_state`,
`persist_upload_state`, the batch functions, and the recovery functions. Stored at
`/tmp/single_ra_isi/<upload_id>/state.json` and `s3://<bucket>/single_ra_isi/<upload_id>/state.json`.

### Top level

| Key | Type | Set by | Notes |
|-----|------|--------|-------|
| `upload_id` | `str` (uuid) | create | |
| `pipeline` | `str` | create | one of the 5 pipeline values |
| `phase` | `str` | create | gsearch phase, else `"all"` |
| `created_at` / `updated_at` | ISO8601 UTC | create / every persist | |
| `status` | `str` | `summarize_upload_state` | `queued` → `processing` → `completed` / `completed_with_errors` |
| `total_rows` / `processed_rows` / `success_rows` / `failed_rows` | `int` | `summarize_upload_state` (`app.py:5337`) | recomputed from rows on every persist |
| `rows` | `list` | create | see row schema below |
| `gemini_batch` | `dict?` | create (full only) + batch fns | see §4 |
| `queue_recovery` | `dict?` | `maybe_requeue_stuck_queued_rows` | `{attempts, last_requeue_at, last_requeued_rows, last_publish_errors}` |
| `gemini_batch_recovery` | `dict?` | the partial-batch helper script only | summary of a partial re-batch run |

`status` derivation (`app.py:5346`): `processed==0` → `queued`; `processed<total` → `processing`;
all processed & `failed==0` → `completed`; else `completed_with_errors`. A row counts as
*processed* when its status is `completed` **or** `failed`.

### Row schema (`app.py:6376`)

| Key | Type | Notes |
|-----|------|-------|
| `row_index` | `int` | 1-based, preserves input order |
| `company_name`, `country`, `firm_id`, `industry`, `full_address` | `str` | from CSV |
| `official_website` | `str` | input URL (firmographics) else `""` |
| `status` | `str` | `queued` / `processing` / `completed` / `failed` |
| `status_updated_at` | ISO8601 | |
| `processing_started_at` | ISO8601 / `null` | set when → processing, cleared on terminal |
| `error` | `str?` | failure reason or batch-pending note |
| `s3_html_key` | `str?` | **alias** of `s3_serpwow_json_key` (back-compat) |
| `s3_serpwow_json_key` | `str?` | S3 key of the per-row raw SerpWow JSON |
| `result` | `dict?` | the `CrawlResponse.model_dump()` (+ s3 keys), see §1 & §5 |

## 4. `gemini_batch` object

Lifecycle states written by the batch functions (`app.py:4704` onward):

| Status | When |
|--------|------|
| `waiting_for_rows` | set at upload time for `full` uploads when batch enabled (`app.py:6397`) |
| `queued` | `maybe_start_gemini_batch_for_upload` scheduled the task (`app.py:5040`) |
| `running` | job submitted / resumed (`app.py:4718`,`4772`) |
| `succeeded` | rows rewritten from batch output (`app.py:4981`) |
| `failed` | error or non-success terminal state (`app.py:5013`) |
| `skipped` | no rows to batch (`app.py:4730`) |
| `cancel_requested` | user cancelled (`app.py:6856`) |

Shape (varies by state):
```json
{ "status": "succeeded", "started_at": "...", "completed_at": "...",
  "job_name": "batches/xxxx", "error": null,
  "usage": {"promptTokenCount": 868650, "candidatesTokenCount": 130674},
  "batch_cost_usd": 0.1391346 }
```

## 5. `result.context` — the diagnostic tree

The `context` dict inside each row's `result` records every step. Keys vary by pipeline; the
**full** pipeline produces the richest tree (verified against `input.json`):

```
context
├── search_url                 # last SerpWow search_url used
├── search_attempts[]          # one entry per query attempted (see below)
├── status_code                # last SerpWow HTTP status
├── success                    # bool
├── used_proxy                 # always false
├── ai                         # {provider:"serpwow", used, error, raw}  (the chosen search response)
├── serpwow                    # codetails firmographics lookup result (run_serpwow_from_codetails)
├── serpwow_mapping_ai         # {provider:"google-gemini", model, used, error, usage, raw}
├── gmaps                      # run_gmaps_from_module result (provider, used, query, official_website,
│                              #   request_count, raw_response, error)
├── transliteration_ai         # {provider, model, used, error, usage, raw:{company_name_transliterated,…}}
├── address_classification_ai  # {…, raw:{country_format_validity,is_complete,completeness_level,address_type,reason}}
├── transliterated_inputs      # {company_name, full_address}  (the working values used)
├── parsed_city_state_ai       # {…, raw:{city,state,confidence,reason}}
├── final_url_selection_ai     # {…, raw:{official_website,confidence_score,confidence,reason,evidence[],alternatives[]}}
├── gemini_batch_ai            # {provider:"google-gemini-batch", model, used, usage, cost_usd, raw, error}
│                              #   (added by the batch step; raw = the full per-row batch JSON)
├── cost_breakdown             # see below
└── timing                     # {total_seconds: float} — total per-row processing time, stamped by
                               #   the worker (process_upload_job) for ALL pipelines. Surfaced in the
                               #   XLSX `output_processing_seconds` column. (Sync /crawl* responses omit it.)
```

`search_attempts[]` entry (`app.py:3143`):
```json
{ "attempt": "phase1_exact_hook", "query": "...", "search_url": "...",
  "status": "official_website_found" | "no_valid_website",
  "used_proxy": false, "status_code": 200, "error": null,
  "official_website": "https://..." | null }
```

`cost_breakdown` (`app.py:3768`, augmented by batch at `app.py:4943`):
```json
{ "massive_proxy_cost_usd": 0.0,
  "serpwow_cost_usd": 0.0,
  "gemini_cost_usd": 0.0,
  "transliteration_ai_cost_usd": 0.0,
  "address_classification_ai_cost_usd": 0.0,
  "parsed_city_state_ai_cost_usd": 0.0,
  "final_url_selection_ai_cost_usd": 0.0,
  "gemini_batch_cost_usd": 0.0,   // added only after the batch step
  "total_cost_usd": 0.0,
  "serpwow_request_count": 0 }
```

The smaller pipelines produce reduced contexts:
- **url_discovery**: same as full minus the firmographics (`serpwow`, `serpwow_mapping_ai`) data;
  includes `"pipeline": "url_discovery"`.
- **firmographics** (`app.py:2789`): `{pipeline, serpwow, serpwow_mapping_ai, cost_breakdown}`.
- **gmaps** (`app.py:2617`): `{pipeline, success, used_proxy, blocked, error, gmaps, cost_breakdown}`.
- **gsearch** (`app.py:2530`): `{pipeline, phase, success, used_proxy, blocked, candidates[], formatted_results[], cost_breakdown}`.

## 6. `output.json` — the combined export (`build_upload_output_payload`, `app.py:4005`)

A reshaped, client-facing view of `state.json`. Written to disk/S3 only when the upload is
terminal (`persist_upload_state`, `app.py:5477`); otherwise `GET /uploads/{id}/output` builds it
on demand.

```json
{
  "upload_id": "...", "pipeline": "full", "status": "completed",
  "gemini_batch": { ... },
  "created_at": "...", "updated_at": "...",
  "total_rows": 124, "processed_rows": 124, "success_rows": 124, "failed_rows": 0,
  "results": [
    {
      "row_index": 1,
      "input": { "company_name", "country", "firm_id", "industry", "full_address", "official_website" },
      "status": "completed",
      "error": null,
      "s3_html_key": "...", "s3_serpwow_json_key": "...",
      "output": { ...the CrawlResponse result with full context... }
    }
  ]
}
```

`input.json` in the repo root is a real example of this shape (124 companies) — see
[10.data-files-and-artifacts.md](10.data-files-and-artifacts.md).

## 7. XLSX export columns (`build_upload_output_xlsx_bytes`, `app.py:4069`)

One sheet named `results`. Header row + one row per result. Column order:

```
upload_id, file_status, batch_status, created_at, updated_at,
total_rows, processed_rows, success_rows, failed_rows,
row_index, input_company_name, input_country, input_firm_id, input_industry,
input_full_address, input_official_website, row_status, row_error,
s3_html_key, s3_serpwow_json_key,
output_official_website, output_confidence_score, output_confidence, output_summary,
output_website_company_descirption_ai, output_website_company_descirption_translated_ai,
output_address, output_phone, output_email, output_industry,
output_products, output_services,
output_massive_proxy_cost_usd, output_serpwow_cost_usd, output_gemini_cost_usd,
output_total_cost_usd, output_processing_seconds, output_json
```

- `output_confidence_score` / `output_confidence` are read from
  `context.final_url_selection_ai.raw`, falling back to `context.gemini_batch_ai.raw`.
- `output_products` / `output_services` are comma-joined.
- `output_processing_seconds` is `context.timing.total_seconds` — total per-row processing time
  stamped by the worker for every pipeline (`app.py` `process_upload_job`).
- `output_json` is the full `result` dict serialized (ASCII).
- The writer is hand-rolled OOXML (`zipfile` of `[Content_Types].xml`, `_rels/.rels`,
  `xl/workbook.xml`, `xl/_rels/workbook.xml.rels`, `xl/worksheets/sheet1.xml`, `xl/styles.xml`).
  Cells are `inlineStr` except numbers/bools; text is sanitized of XML-illegal control chars and
  capped at 32,767 chars (`_sanitize_excel_text`, `app.py:4039`).

## 8. CSV input formats

### Standard pipelines — `parse_csv_rows` (`app.py:5162`)
Header names are normalized (`_normalize_header`: lowercase, non-alphanumerics → `_`). It looks
for, in order of preference:

| Logical field | Accepted header aliases |
|---------------|-------------------------|
| company name | `company_name`, `company`, `name`, `entity_name`, `entity`, `organization`, `organisation`, `legal_name` |
| country | `country`, `country_name`, `nation` |
| firm_id | `firm_id`, `firmid`, `id` |
| industry | `industry`, `input_industry` |
| full_address | `full_address`, `address`, `fulladdress`, `input_full_address` |

Requires **company + country** columns. If a header-based parse yields nothing, it falls back to
treating the **first two columns** as company/country (skipping a header-like first row). Rows
with an empty company name are dropped. Raises `ValueError` (→ HTTP 400) if no usable rows.

### Firmographics pipeline — `parse_firmographics_csv_rows` (`app.py:5263`)
Requires a website column: `official_website`, `website`, `url`, or `domain`. Other columns
optional (same aliases as above). The URL is normalized via `_normalize_website_input`
(adds `https://`, strips trailing `/`). If `company_name` is absent it defaults to the URL's
domain. Raises `ValueError` if no row has a valid website.

> The UI's "expected columns" hints (`company_name`, `country`, `input_full_address`,
> `input_industry`, `firm_id`) match these aliases. The bundled CSVs use exactly these headers —
> see [10](10.data-files-and-artifacts.md).

## 9. S3 artifact layout

All under `s3://<S3_BUCKET>/single_ra_isi/<upload_id>/` (key builders at `app.py:409`–423,
`3979`):

| Key | Builder | Content |
|-----|---------|---------|
| `state.json` | `_state_s3_key` | the state object (§3) |
| `output.json` | `_output_s3_key` | the combined output (§6), written when terminal |
| `gemini_batch_input.jsonl` | `_batch_input_jsonl_s3_key` | one JSON line per batched row (the request) |
| `gemini_batch_output.json` | `_batch_output_json_s3_key` | the raw final batch object from Gemini |
| `<row:05d>_<safe_company>_serpwow.json` | `_upload_serpwow_json_sync` | per-row raw SerpWow/GMaps response |

The same files (minus the per-row raw, which goes only to S3) are also kept under
`/tmp/single_ra_isi/<upload_id>/` for fast local reads.
