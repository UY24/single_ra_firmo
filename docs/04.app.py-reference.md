# 04 · `app.py` reference (7,470 lines)

`app.py` is the entire backend in one module: configuration, the URL-discovery pipeline, all
Gemini helpers, the SerpWow client, S3 + local state persistence, the RabbitMQ producer/worker,
Gemini batch post-processing, the XLSX writer, and every FastAPI endpoint.

This is a **reference**: every function, grouped by the order it appears, with its line anchor,
signature intent, and behavior. The narrative *flow* (how these compose into a pipeline) lives in
[05.pipelines-and-flow.md](05.pipelines-and-flow.md); the HTTP surface is fully detailed in
[06.api-endpoints.md](06.api-endpoints.md).

Convention: `name(args) -> ret` · **L#** = line. Private helpers are prefixed `_`.

---

## 1. Imports & module bootstrap (L1–77)

- **Imports**: stdlib (`asyncio`, `csv`, `io`, `json`, `os`, `re`, `uuid`, `zipfile`, `datetime`,
  `pathlib`, `typing`, `urllib.*`, `xml.sax.saxutils.escape`) + third-party `aio_pika`, `boto3`,
  `httpx`, `botocore.config.Config`, `aiormq.exceptions.ChannelInvalidStateError`, `fastapi`,
  `pydantic`.
- **`load_local_env(env_path=".env")` (L26)** — minimal dotenv: sets each `KEY=VALUE` into
  `os.environ` only if missing or empty; strips quotes. Called at L46. (See
  [02.configuration.md](02.configuration.md) for the blank-value gotcha.)
- **`app = FastAPI(title="Single RA ISI API", version="2.0.0")` (L47)**.
- Constants: `UPLOAD_BASE_DIR = /tmp/single_ra_isi` (L49, created at import),
  `S3_PREFIX = "single_ra_isi"` (L51), `UI_TEMPLATE_PATH = templates/ui.html` (L52).
- **`upload_locks` + `get_upload_lock(upload_id) -> asyncio.Lock` (L54–59)** — per-upload async
  lock so concurrent row writes to the same `state.json` serialize. Locks are created lazily and
  never evicted.
- **Module globals (L61–77):** RabbitMQ connection/channel/exchange/queue, `rabbitmq_consumer_tasks`,
  `rabbitmq_last_error`, `rabbitmq_stop_event`; `search_fetch_semaphore`; `gemini_batch_tasks`
  (upload_id → asyncio.Task); `upload_active_rows` (upload_id → set of row indices currently being
  processed) + its lock; `upload_summaries_cache`; the Gemini batch-list cache + timestamps;
  `s3_client` (lazily created singleton).

## 4. `patch_aio_pika_connection_del()` (L128, called L164)
Monkey-patches `aio_pika`'s `Connection.__del__` so GC during interpreter/thread shutdown (when no
event loop is running) doesn't raise `RuntimeError`/leak coroutine warnings. Idempotent
(guards with a `_safe_del_patched` flag).

## 8. SerpWow search: extraction + client (L434–663)

URL extraction from a raw SerpWow search response, in priority order knowledge_graph → answer_box
→ ai_overview sources → organic results (skipping listings/profiles):
- `_extract_official_website_from_serpwow(data)` (L434) — first allowed URL by that priority.
- `_serpwow_ai_overview_is_ambiguous(data)` (L469) — detects "multiple/similar entities", "no
  single verified URL", etc. in the AI-overview text; if ambiguous, the caller discards the URL.
- `_is_listing_or_profile_result(result)` (L496) — true for directory/profile/trade-data results
  (by title/snippet keywords or path markers like `/company/`, `/directory/`).
- `_extract_official_website_candidates_from_serpwow(data)` (L537) — all allowed candidates
  (deduped, ordered) across the same sources.
- **`run_serpwow_search(query, country=None, client=None) -> dict` (L580)** — the core SerpWow
  search call. Builds params (`engine=google`, `include_ai_overview=true`, `gl=_country_to_gl`),
  throttles via `search_fetch_semaphore`, returns a uniform dict `{provider, used, query,
  official_website, candidates[], status_code, search_url, raw_response, error}`. On ambiguity it
  nulls `official_website` but keeps candidates. Creates its own `httpx.AsyncClient` if none given.
- Query builders: `build_primary_search_query` (L653), `build_industry_fallback_query` (L657),
  `build_address_fallback_query` (L661).

## 9. URL/domain normalization & plausibility (L665–719)
- `_normalized_domain(url_or_domain)` (L665) — host without scheme/`www.`/path.
- `_normalize_url_for_compare(url)` (L678) — `scheme://host/path` (no trailing slash, no `www.`).
- `_candidate_domain_is_plausible_for_company(domain, company_name, country)` (L693) — **plausibility
  gate**: true if any meaningful company token (≥4 chars, not generic) appears in the host, or
  (with tokens present) the host ends in the country ccTLD.
- `_official_website_looks_plausible(url, company_name, country)` (L715) — wrapper over the above.
  This is applied to nearly every candidate URL before it's accepted.

## 10. Address parsing & the investigative query builder (L722–1117)

Helpers that mine the free-text `full_address` and company name into search "dorks":
- `_extract_address_search_fragments` (L722), `_append_unique_attempt_query` (L763, dedupes
  queries by normalized text), `_company_name_variants` (L779, builds initials variants like
  `A.B.C.`/`ABC`), `_extract_address_component(addr, keywords)` (L803), `_marker_variants` (L812,
  produces hyphen + spaced forms like `Plot-16` / `Plot 16`), `_extract_locality_city_postal`
  (L838), `_looks_like_person_name` (L875), `_extract_phase5_pivots_from_serpwow` (L890, mines
  organic/AI titles for person names and corporate trade names to drive phase-5 expansion).
- **`build_investigative_search_queries(company_name, country, parsed_city_state="",
  full_address="", industry="", max_queries=10) -> list[(label, query)]` (L948)** — assembles the
  phase-1…phase-4 query battery (+ industry fallback), deduped, capped at `max_queries`. This is
  the query set used by the **full / url_discovery** worker pipeline. (Phases explained in
  [05](05.pipelines-and-flow.md). A parallel, phase-selectable variant
  `build_selected_phase_queries` lives at L7096 for the gsearch pipeline.)

## 11. Location normalization & address-alignment (L1120–1378)
- `_normalize_location_token` (L1120), `_dedupe_location_parts` (L1126),
  `_is_suspicious_city_state_value` (L1141, flags street-level fragments mis-parsed as city/state),
  `_heuristic_city_state_from_full_address` (L1159, fallback city/state from the last comma parts).
- Address matching: `_address_evidence_markers` (L1178, extracts strong markers like `plot 16`,

  **`_is_address_aligned(input_full_address, candidate_address)` (L1238)** — true if the candidate
  address contains the input's strong markers (used to reject URLs whose address conflicts).
- `_meaningful_company_tokens` (L1262), `_extract_address_numbers` (L1289).
- **`_select_best_gmaps_website(gmaps_result, company_name, input_full_address)` (L1300)** — scores
  each GMaps place by company-token / address-number / marker matches, penalizes
  org-type mismatches (chamber/embassy/university…), returns the best website URL.

## 12. `is_disallowed_official_url(url)` (L1381)
The **URL blocklist gate** used everywhere a candidate is considered. Rejects: non-http(s);
Google domains; a list of social/data-broker/directory domains (linkedin, facebook, zoominfo,
crunchbase, yellowpages, opencorporates, zaubacorp, eximpedia, scribd, …); direct file URLs
(`.pdf/.doc/.xls/...`); document/upload paths; and query-param file downloads.

## 13. `_parse_json_from_text(raw_text)` (L1478)
Strips ```` ```json ```` fences and `json.loads` → dict or `None`. Used to parse every Gemini
text response.

## 14. Cost calculators (L1491–1533)
- `calculate_gemini_cost_usd(usage)` (L1491) — per-row Gemini cost from `promptTokenCount` /
  `candidatesTokenCount` × the per-1M prices.
- `calculate_gemini_batch_cost_usd(usage)` (L1507) — same, using batch prices (falling back to the
  non-batch prices).
- `calculate_serpwow_cost_usd(requests)` (L1529) — `requests × SERPWOW_USD_PER_REQUEST`.

`urllib` (45 s timeout); parse JSON; return `(normalized_dict_or_None, error_or_None, model,
usage_metadata)`.

## 16. Domain & external-integration wrappers (L2216–2390)
- `_domain_from_url(url)` (L2216).
- **`run_serpwow_from_codetails(official_website, country=None)` (L2224)** — imports `codetails.py`
  and runs its AI-overview firmographics query for the URL's domain (with one placeholder-retry).

- **`run_gmaps_from_module(company_name, country, …)` (L2312)** — imports `gmaps.py`, builds a

## 17. Pipeline executors (L2392–3797)
Each returns `(CrawlResponse, serpwow_raw_json_string)`. The worker calls one of these per row.

- **`execute_gsearch_lookup_for_worker(...phase="all")` (L2392)** — runs the queries from
  `build_selected_phase_queries` for the selected phase (with special phase-5 pivot expansion),
  fires them in parallel, collects unique allowed candidates, and returns the first candidate as
  the "official_website" with a `PIPELINE_GSEARCH` context. No Gemini, no firmographics. (Cost is
  a flat `0.02`/query placeholder — note it does **not** use `calculate_serpwow_cost_usd`.)
- **`execute_gmaps_lookup(...)` (L2557)** — GMaps-only via `run_gmaps_from_module`; extracts
  website/address/phone/category from the first place; `PIPELINE_GMAPS` context. Cost via
  `calculate_serpwow_cost_usd(request_count)`.
- **`execute_firmographic_extraction(official_website, ...)` (L2638)** — validates the URL
  (rejects disallowed), runs `run_serpwow_from_codetails`, maps the AI-overview via
  `standardize_serpwow_ai_overview_with_gemini`, optionally warns if the mapped address isn't
  aligned with the input address. `PIPELINE_FIRMOGRAPHICS` context.
- **`execute_company_lookup(company_name, country, …, include_firmographics=True)` (L2806)** — the
  **core URL-discovery pipeline** (≈1,000 lines). High-level steps:
  1. transliterate inputs (L2846); 2. classify address (L2891); 3. parse city/state with heuristic
     fallback (L2929); 4. build the investigative query battery (L2972) and optionally a
     non-transliterated "phase0" probe (L2994); 5. fire all queries in parallel via
     `run_serpwow_search`, processed by the **inner closure `_process_serpwow_attempt_result`**
     (L3073) which accepts plausible URLs, records attempts, and dynamically appends **phase-5**
     queries (person/trade-name/candidate-verification) which are then run in a second parallel
     wave (L3268); 6. GMaps enrichment, possibly replacing the URL (L3296); 7. dedupe candidates;
     8. `choose_final_website_with_gemini` confidence pick (skipped if batch post-processing is on)
     (L3358); 9. early returns for "no URL found" (L3437) and `include_firmographics=False`
     (L3523); 10. firmographics enrichment via codetails + Gemini mapping (L3596), with an
     **address-alignment guard** (L3665) that can null the URL if the mapped address conflicts;
     11. assemble `CrawlResponse` with full cost breakdown + context. Emits `_log_row_stage` at
     every step. Detailed walkthrough in [05](05.pipelines-and-flow.md).

## 20. Gemini batch post-processing (L4280–5155)
- **`_build_batch_prompt_for_row(row)` (L4280)** — builds the per-row resolver+profile prompt
  (collects candidate URLs from gmaps/current/attempts, embeds search/serpwow/gmaps context,
  and demands the bilingual ≥250-char descriptions per the brief).
- `_build_batch_requests_for_state(state)` (L4361) — one request per `completed`/`failed` row;

- Sync REST wrappers: `_gemini_batch_create_sync` (L4397, `:batchGenerateContent`),
  `_gemini_batch_get_sync` (L4433), `_gemini_batch_cancel_sync` (L4444), `_gemini_batch_delete_sync`
  (L4462), `_gemini_batch_list_sync` (L4479, paginated).
- Response parsing: `_extract_text_from_generate_response` (L4519), `_gemini_batch_state_name`
  (L4534, handles old `state.name` and new LRO `metadata.state`), `_gemini_batch_is_terminal`
  (L4559), `_gemini_batch_is_success` (L4575), `_extract_upload_id_from_batch_obj` (L4585, parses
  the `single-ra-upload-<id>-<uuid>` display name), `_derive_ui_batch_status` (L4601),
  `_extract_batch_inlined_responses` (L4633, handles several response shapes),
  `_extract_batch_response_key` (L4672).
- `_log_gemini_batch` (L4700).
- **`run_gemini_batch_for_upload(upload_id)` (L4704)** — the batch driver: set `running`, build
  requests (or `skipped` if none), write the input JSONL artifact, create the job (or resume an
  existing `job_name`), poll to a terminal state (with transient-error tolerance and timeout),
  write the output artifact, map responses back to rows (by `metadata.key`, with index fallback),
  rewrite each row's URL (re-validating plausibility) + summary + descriptions + firmographics +
  costs, and set `gemini_batch.status="succeeded"`. On any error, sets `failed`. Always pops the
  task from `gemini_batch_tasks` in `finally`.
- `maybe_start_gemini_batch_for_upload(upload_id, state)` (L5027) — schedules the batch task when a
  `full` upload is terminal and batch is enabled and not already running/done.
- `maybe_resume_gemini_batch_for_upload` (L5049) — re-attach a task for a `running` job after a
  restart.
- `maybe_reconcile_gemini_batch_status(upload_id, state)` (L5067) — fetch live job state, map to a
  UI status, persist if changed; also auto-fails a `running`-with-no-`job_name` job older than

## 22. RabbitMQ producer + worker (L5805–6233)
- `_build_rabbitmq_url` (L5805) / `get_rabbitmq_url` (L5810) — build the AMQP URL.
- **`init_rabbitmq()` (L5819)** — robust-connect (with localhost guest/guest fallback), open
  channel, set QoS prefetch = `WORKER_CONCURRENCY`, declare durable direct exchange + durable
  queue, bind on the routing key.
- `close_rabbitmq()` (L5862) — stop consumers, drop refs, close connection.
- **`publish_job(job)` (L5876)** — publish a persistent JSON message (5 s timeout wrapper).
- **`process_upload_job(job)` (L5905)** — the per-row worker body: idempotency skip for terminal
  rows; mark `processing`; dispatch to the pipeline executor by `pipeline`; upload per-row raw
  JSON to S3; decide terminal status (with the batch-pending exception); `update_row_state`;
  re-raises on exception so the consumer can nack.
- **`rabbitmq_worker_loop(worker_id)` (L6066)** — registers a real consumer via
  `queue.iterator()`; for each message: track active row, run `process_upload_job` under
  `WORKER_JOB_TIMEOUT_SEC`, ack on success; on error nack-requeue once then drop-on-redelivery; on
  cancel nack-requeue and re-raise.
- `start_worker_consumers(worker_count=None)` (L6193) / `stop_worker_consumers()` (L6209) — spawn
  `WORKER_CONCURRENCY` loop tasks / stop them gracefully.

## 23. FastAPI lifecycle + endpoints (L6236–7470)
- `@app.on_event("startup") startup_event()` (L6236) — create the search semaphore, `init_rabbitmq`,
  and start consumers only if `ENABLE_EMBEDDED_WORKER`.
- `@app.on_event("shutdown") shutdown_event()` (L6253) — cancel batch tasks, `close_rabbitmq`.
- **Endpoints** (L6263–7462) — health, `/ui`, `/get-url/`, `/crawl` (GET/POST),
  `/crawl/url-discovery`, `/crawl/firmographics`, the upload creators (`/uploads`,
  `/uploads/url-discovery`, `/uploads/firmographics`, `/uploads/gmaps`, `/uploads/gsearch`),
  `/uploads/{id}/retry-failed-rows`, `GET /uploads` (list), the `/batch/jobs*` management
  endpoints, `/uploads/{id}/status`, `/uploads/{id}/failure-analysis`, `/uploads/{id}/output`, and
  the standalone `/gmaps/*` and `/gsearch/discover` tools. Shared upload-creation logic is
  `_create_upload_with_rows` (L6337). All detailed in [06.api-endpoints.md](06.api-endpoints.md).
- `build_selected_phase_queries(...phase="all")` (L7096) — phase-selectable query builder used by
  the gsearch endpoint/pipeline (handles the no-address case explicitly, unlike
  `build_investigative_search_queries`).
- `if __name__ == "__main__":` (L7465) — `uvicorn.run("app:app", host=API_HOST, port=API_PORT)`.
