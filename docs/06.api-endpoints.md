# 06 · HTTP API endpoints

All endpoints are defined in `app.py` on the `FastAPI` instance (`app`). FastAPI auto-generates
OpenAPI docs at `/docs` and `/redoc`. Base URL = `http://<API_HOST>:<API_PORT>` (default
`0.0.0.0:11500`, or `:14000` if `.env.example` values are used).

Models referenced below (`CrawlRequest`, `FirmographicsRequest`, `CrawlResponse`) are in
[03.data-models.md](03.data-models.md). The upload/state/output/batch shapes are there too.

## 2. Synchronous single-company endpoints

These run a **full pipeline inline in the request** (no queue) and return a `CrawlResponse`. They
can be slow (many SerpWow + Gemini calls) and are mainly for testing/integration.

| Method · Path | L# | Input | Behavior |
|---|---|---|---|
| `GET /crawl` | 6281 | query: `company_name`, `country`, `firm_id?`, `industry?`, `full_address?` | `execute_company_lookup(...)` with firmographics. |
| `POST /crawl` | 6299 | body: `CrawlRequest` | Same as `GET /crawl`. |
| `POST /crawl/url-discovery` | 6311 | body: `CrawlRequest` | `execute_company_lookup(include_firmographics=False)` — URL only. |
| `POST /crawl/firmographics` | 6324 | body: `FirmographicsRequest` | `execute_firmographic_extraction(...)` from a given URL. |

## 3. Batch upload creators (CSV → queue)

All accept `multipart/form-data` with field **`file`** (must be `.csv`). They parse the CSV, create
an upload `state.json`, publish one RabbitMQ job per row, and return an upload receipt. Shared
logic: `_create_upload_with_rows` (`app.py:6337`).

| Method · Path | L# | Pipeline | CSV parser | Extra |
|---|---|---|---|---|
| `POST /uploads` | 6460 | `full` | `parse_csv_rows` | sets `gemini_batch.waiting_for_rows` if batch enabled |
| `POST /uploads/url-discovery` | 6470 | `url_discovery` | `parse_csv_rows` | |
| `POST /uploads/firmographics` | 6480 | `firmographics` | `parse_firmographics_csv_rows` | requires a website column |
| `POST /uploads/gmaps` | 6490 | `gmaps` | `parse_csv_rows` | |
| `POST /uploads/gsearch` | 6500 | `gsearch` | `parse_csv_rows` | also form field **`phase`** (default `"all"`) |

**Response** (all of them):
```json
{ "upload_id": "...", "filename": "x.csv", "total_rows": 124,
  "enqueued_rows": 124, "enqueue_errors": [],
  "status_url": "/uploads/.../status",
  "output_url": "/uploads/.../output",
  "output_xlsx_url": "/uploads/.../output?format=xlsx" }
```

**Errors:** `400` if the file isn't `.csv` or the CSV has no usable rows (`ValueError` from the
parser); `503` if RabbitMQ isn't connected (`rabbitmq_exchange is None`), with the last RabbitMQ
error appended. Per-row publish failures don't fail the request — those rows are marked `failed`
("Queue publish failed: …") and listed in `enqueue_errors`.

### Retry

| Method · Path | L# | Query | Returns |
|---|---|---|---|
| `POST /uploads/{upload_id}/retry-failed-rows` | 6513 | `limit` (0–5000, 0 = all) | re-queues rows whose status ∈ {failed, queued, processing}; resets `gemini_batch` to `waiting_for_rows` for full uploads. Returns `{upload_id, requested_retry_rows, enqueued_rows, enqueue_errors, retry_row_indexes, status_url, failure_analysis_url}`. `404` if upload unknown, `503` if RabbitMQ down. |

## 4. Upload status / output / analysis

| Method · Path | L# | Query | Returns / behavior |
|---|---|---|---|
| `GET /uploads` | 6632 | `limit` (1–500, def 100), `pipeline?` | `{count, uploads:[summary]}`. `pipeline` filters to one of the 5 values. Summaries come from `list_upload_summaries` (cached, local-first). |
| `GET /uploads/{upload_id}/status` | 6925 | — | The **heartbeat** endpoint. Runs `maybe_resume_gemini_batch` → `maybe_reconcile_gemini_batch_status` → `maybe_requeue_stuck_queued_rows` → `maybe_fail_stale_processing_rows`, then returns the full status incl. `rows[]`, `gemini_batch`, `queue_recovery`, counters. `404` if unknown. |
| `GET /uploads/{upload_id}/failure-analysis` | 6976 | `sample_limit` (1–100, def 20) | Same recovery passes, then `build_failure_analysis`: `{failed_rate_pct, error_buckets[], search_attempt_error_buckets[], sample_failed_rows[], …}`. `404` if unknown. |
| `GET /uploads/{upload_id}/output` | 7001 | `download` (bool), `format` (`json`\|`xlsx`) | Returns the combined output. Prefers the persisted `output.json`; if absent, builds it on demand from state. `xlsx` builds the workbook via `build_upload_output_xlsx_bytes`. `download=true` adds a `Content-Disposition` attachment header. `404` if neither output nor state exists. |

## 5. Gemini batch management

| Method · Path | L# | Input | Returns |
|---|---|---|---|
| `GET /batch/jobs` | 6646 | `limit` (1–500, def 200) | Merge of the remote Gemini batch list (cached, optional via `ENABLE_REMOTE_GEMINI_BATCH_LIST`) and locally-tracked full uploads' jobs. `{count, jobs[], source: "remote"\|"local_fallback", remote_error}`. Each job: `{upload_id, upload_status, batch_status, job_name, live_state, done, updated_at, started_at, completed_at, error}`. |
| `POST /batch/jobs/{upload_id}/status` | 6780 | — | Fetch the live job state for the upload's `job_name`, reconcile/persist, return `{upload_id, job_name, batch_status, live_state, done, raw}`. `400` if no job, `404` if unknown upload, `502` on Gemini error. |
| `POST /batch/jobs/{upload_id}/cancel` | 6835 | — | Cancel the upload's batch job; set local status `cancel_requested`. `400`/`404`/`502` as above. |
| `POST /batch/jobs/status` | 6875 | query `job_name` | Live status by raw job name (not tied to an upload). `502` on Gemini error. |
| `POST /batch/jobs/cancel` | 6899 | query `job_name` | Cancel by job name. |
| `POST /batch/jobs/delete` | 6912 | query `job_name` | Delete the Gemini batch by job name. |

(Note these are **POST** even for "status"/"get" — the UI calls them with `method: 'POST'`.)

## 6. Standalone SerpWow / Google tools

Diagnostic endpoints used by the UI's "Google Maps Lookup" and "Google Search Phases" tabs. All
require `SERPWOW_API_KEY` (else `400`).

| Method · Path | L# | Query | Returns |
|---|---|---|---|
| `GET /gmaps/discover` | 7045 | `q`, `country?` | `{query, gl, cids:[...]}` — Google Maps place CIDs for the query (`gmaps.fetch_data_cids`). |
| `GET /gmaps/details` | 7063 | `cid` | The filtered place-details dict for one CID (`gmaps.fetch_place_detail`). |
| `GET /gmaps/search` | 7082 | `q`, `country?` | Full `gmaps.process_gmaps_query` result `{query, gl, request_count, total_places, results[]}`. |
| `GET /gsearch/discover` | 7340 | `company_name`, `country`, `parsed_city_state?`, `full_address?`, `industry?`, `phase` (def `all`), `people?[]`, `trade_names?[]` | Runs the selected phase's queries (phase-5 builds people/trade pivots, auto-seeded from a phase-1 probe if none supplied). `{company_name, country, phase, queries_run, candidates[], results[]}`. `500` on internal error. |

## 7. Error-code summary

| Code | When |
|------|------|
| `400` | Non-CSV upload / empty CSV (`ValueError`); missing `SERPWOW_API_KEY` for gmaps/gsearch tools; "No Gemini batch job found for upload". |
| `404` | Unknown `upload_id` (status/output/failure-analysis/retry/batch-by-upload). |
| `500` | UI template missing; unhandled error in the `/gmaps/*` tools. |
| `502` | Gemini batch status/cancel/delete API failures. |
| `503` | RabbitMQ not connected when creating/retrying uploads. |

## 8. Typical client sequence (UI or script)

```
POST /uploads (file=companies.csv)            → {upload_id}
loop every 2s:
  GET /uploads/{upload_id}/status             → status, counts, gemini_batch
  until status ∈ {completed, completed_with_errors} AND gemini_batch.status terminal
GET /uploads/{upload_id}/output?format=xlsx&download=true   → workbook
# optional
GET /uploads/{upload_id}/failure-analysis     → why rows failed
POST /uploads/{upload_id}/retry-failed-rows   → re-queue failures
```
