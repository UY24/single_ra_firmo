# 07 · The web UI (`templates/ui.html`)

`templates/ui.html` (2,029 lines) is a **single self-contained page** — inline CSS + vanilla
JavaScript, no build step, no framework, no external JS. It is served verbatim by `GET /ui`
(`app.py:6268`). It talks to the same-origin API with `fetch`.

> `templates/ui copy.html` (523 lines) is a **legacy backup** — an earlier light-themed design
> (Space Grotesk font, cream/orange palette). It is **not** referenced by `app.py` and is not
> served. Ignore it for the live product.

## 1. Layout

- **Hero** header ("Company Url Discovery") + a tab bar (`.tabs`) with six buttons.
- Dark theme via CSS custom properties in `:root` (`--bg`, `--accent`, `--good`, `--bad`, …),
  JetBrains Mono + Syne fonts loaded from Google Fonts, subtle scanline/radial-gradient texture.
- Six `.view` panels, one per tab; `setActiveTab(tab)` toggles the `.hidden` class so exactly one
  view shows (`ui.html:997`).

## 2. The six tabs

| Tab button id | View id | `activeTab` | Purpose |
|---------------|---------|-------------|---------|
| `tabConsole` | `consoleView` | `console` | **Upload Console** — the main `full` pipeline: upload CSV, live progress (chips, progress bar, 4 stat cards), an uploads history table, and JSON/XLSX download links. |
| `tabFirmographics` | `firmographicsView` | `firmographics` | **Firmographics Upload** — upload a CSV of URLs to the firmographics pipeline; history table. |
| `tabBatchManager` | `batchManagerView` | `batch` | **Batch Manager** — table of Gemini batch jobs with Get-Status / Cancel / Delete actions. |
| `tabGmapsSearch` | `gmapsSearchView` | `gmaps` | **Google Maps Lookup** — batch CSV upload to the gmaps pipeline **plus** standalone Discover / Full Search / Place-Details-by-CID tools that render result cards. |
| `tabGsearchPhases` | `gsearchView` | `gsearch` | **Google Search Phases** — batch CSV upload with a phase selector, **plus** a standalone phase runner that shows candidates and a per-query execution log (organic results + AI overview). |
| `tabRetryOps` | `retryOpsView` | `retry` | **Retry Operations** — paste an `upload_id` and trigger `retry-failed-rows`. |

The expected CSV columns are shown inline under each upload control (matching the parser aliases
in [03 §8](03.data-models.md)).

## 4. Event wiring & polling

- Upload buttons (`uploadBtn`, `firmographicsUploadBtn`, `gmapsUploadBtn`, `gsearchUploadBtn`)
  build a `FormData`, `POST` to the matching `/uploads*` endpoint, then start a `setInterval`
  poller at **2,000 ms** for that upload (`ui.html:1444`, `1476`, `1513`, `1551`).
- The gsearch upload also appends the selected `phase` form field (`ui.html:1521`).
- Batch Manager actions are delegated from the table body (`ui.html:1354`): Cancel/Delete prompt
  for confirmation, then `POST /batch/jobs/{cancel|delete|status}?job_name=...`.
- Retry tab: `POST /uploads/{id}/retry-failed-rows`, then switches to the console tab and starts
  polling that upload (`ui.html:1967`).
- A global `setInterval` at **4,000 ms** (`ui.html:2018`) refreshes all four uploads tables (and
  the batch table when that tab is active), so history stays live regardless of which tab is open.
- On load, all `refresh*` functions run once (`ui.html:2013`).

## 5. Download gating (important UX detail)

For the **console** (`full`) tab, the JSON/XLSX download links only appear when the row status is
terminal **and** `gemini_batch.status ∈ {not_started, succeeded, failed, skipped}` — i.e. the
batch must be done, because the batch is what writes the final URLs and descriptions
(`ui.html:1407`–1421, and `useBatchGate:true` in `renderUploadsTable`). The other pipelines don't
have a batch, so their downloads unlock as soon as rows finish.
