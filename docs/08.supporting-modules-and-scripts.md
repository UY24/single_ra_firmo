# 08 · Supporting modules & scripts

Everything outside `app.py`. These are entrypoints (worker, batch runner), the two SerpWow client
modules `app.py` imports, a one-off converter, and ad-hoc/operational scripts.

---

## 1. `worker.py` — the worker process entrypoint (52 lines)

The standalone consumer process. It `import app` and reuses all of `app.py`'s machinery.

`main()` (async):
1. Install `SIGINT`/`SIGTERM` handlers that set a `stop_event` (best-effort; ignored where the
   platform doesn't support `add_signal_handler`).
2. `await app.startup_event()` — connects RabbitMQ (and, only if `ENABLE_EMBEDDED_WORKER=true`,
   starts consumers there too).
3. `await app.start_worker_consumers()` — spawn `WORKER_CONCURRENCY` consumer tasks. (Idempotent:
   if consumers already exist from step 2 it returns immediately, so there's no double-start.)
4. Wait on `stop_event` **or** any consumer task finishing (`asyncio.wait(FIRST_COMPLETED)`).
   If a consumer crashed, surface its exception and raise `RuntimeError`.
5. `finally`: cancel the wait task, `await app.shutdown_event()` (cancel batch tasks, close
   RabbitMQ).

**Run:** `python worker.py`. This is the process that actually does the SerpWow/Gemini work; the
API process is producer-only by default.

## 2. `batch_runner.py` — manual batch trigger (19 lines)

CLI wrapper: `python batch_runner.py <upload_id>` → `await app.run_gemini_batch_for_upload(
upload_id)`. Forces the Gemini batch step for one upload regardless of the auto-trigger. Prints a
completion line. Useful when batch was disabled at upload time or you want to re-run it.

## 3. `gmaps.py` — SerpWow Google-Maps client (461 lines)

Self-contained module that `app.py` imports as `gmaps` (via `run_gmaps_from_module`) and the
`/gmaps/*` endpoints call directly. Uses `aiohttp` (async) and optional `python-dotenv`/`pyyaml`.

**Config loading (`gmaps.py:45`–91):** reads an optional YAML file at `APP_CONFIG_FILE`
(default `config.yaml`) for:
- `serpwow.place_fields` → `PLACE_FIELDS` (which keys to keep from `place_details`).
- `country_to_gl` → `COUNTRY_TO_GL` (country-name → gl map).

> **There is no `config.yaml` in this repo**, so `PLACE_FIELDS` is **empty** (meaning
> `filter_place_details` returns the *entire* `place_details` dict) and `COUNTRY_TO_GL` is
> **empty** (so country detection relies only on the regex postal heuristics below).

**Exports / key functions:**

| Function | L# | Purpose |
|----------|----|---------|
| `detect_country_from_query(q)` | 120 | Best-effort country from free text; regex fallbacks: `\d{2}-\d{3}`→poland, `\d{6}`→india, `\d{4,5}`→germany, else `united states`. |
| `country_to_gl(country)` | 138 | Country name/2-letter → gl; `us` default. |
| `get_gl_from_query(q)` | 153 | `country_to_gl(detect_country_from_query(q))`. |
| `filter_place_details(data)` | 162 | Keep only `PLACE_FIELDS` from `place_details` (or all, if empty). |

| `fetch_place_detail(session, cid, sem)` | 249 | SerpWow `search_type=place_details` for one CID (semaphore-bounded) → filtered dict or error dict. |
| `process_gmaps_query(q, country=None)` | 307 | Full pipeline: places search → parallel place-detail fetch (semaphore 20). Returns `{query, gl, request_count, total_places, results[]}`. Guards missing API key / aiohttp. |

## 5. `convertjtox.py` — JSON → XLSX flattener (54 lines)

A **one-off** utility, unrelated to the running service. Reads `input.json`, flattens each
`results[*]` (`flatten_json` joins nested dicts with `_` and stringifies lists with ` | `), builds
a `pandas.DataFrame`, and writes `output.xlsx`. Requires `pandas` (+ an Excel engine, e.g.
`openpyxl`). Run: `python convertjtox.py`. (The service itself produces XLSX via the hand-rolled
writer in `app.py`, not this script.)

## 6. `scripts/` — operational & debug helpers

All add the repo root to `sys.path` so they can `import app`. Run with the **same Python
environment** as the server.

| Script | Purpose | Notes |
|--------|---------|-------|
| `debug_s3.py` | Fetch a `state.json` straight from S3 and print its keys / row count. | `upload_id` is **hard-coded** in the file — edit it before running. Verifies S3 connectivity + that state exists. |
| `debug_state.py` | Read an upload's state via `app.read_upload_artifact` and print status/counters/row-status breakdown + first non-terminal rows. | `upload_id` hard-coded. |
| `push_processed_rows_to_gemini_batch.py` | Re-run the Gemini batch for an upload's already-processed rows. | `python scripts/push_processed_rows_to_gemini_batch.py <upload_id> [--force-new-job]`. Requires `pipeline=full`. `--force-new-job` resets `gemini_batch` to `waiting_for_rows` then calls `app.run_gemini_batch_for_upload`. Prints eligible-row counts and the final batch state. **⚠ Bug:** the `--force-new-job` path uses `async with app.upload_lock:` (line 79), but `app` has no `upload_lock` — only `upload_locks` (a dict) and `get_upload_lock(upload_id)` (`app.py:54`). So **`--force-new-job` raises `AttributeError`** and the reset never happens. The default path (no `--force-new-job`) is unaffected and works. Fix: `async with app.get_upload_lock(upload_id):`. |
| `requeue_wait_and_push_remaining_to_gemini_batch.py` | Recover an upload: requeue stuck rows, wait for them to finish, then run a **partial** Gemini batch for only the rows not yet batch-post-processed. | `python scripts/requeue_wait_and_push_remaining_to_gemini_batch.py <upload_id> [--wait-timeout-sec 1800] [--poll-sec 10] [--skip-wait]`. Detects unprocessed rows (`_count_rows`), `init_rabbitmq` if needed, `maybe_requeue_stuck_queued_rows` + `maybe_fail_stale_processing_rows` each tick, waits until all rows terminal, then builds + submits + polls a partial batch. **⚠ Broken on its main path:** `_run_partial_gemini_batch` uses `async with app.upload_lock:` (line 183), and `app.upload_lock` does not exist (only `upload_locks` / `get_upload_lock(upload_id)`, `app.py:54`). The script reaches this line whenever there are rows to batch, so it **raises `AttributeError` after submitting/polling the Gemini batch, before persisting results to state** — the partial batch is wasted. Fix: `async with app.get_upload_lock(upload_id):`. |

`scripts/__pycache__/` holds the cpython-3.12 compiled versions of the two push scripts (a hint
that the runtime is Python 3.12).
