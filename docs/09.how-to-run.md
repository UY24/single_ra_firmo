# 09 · How to run

This is the operational guide: prerequisites, install, configure, run the API + worker, and a full
end-to-end walkthrough. There is **no** `requirements.txt`, `Dockerfile`, or `Makefile` in the
repo, so install is manual.

---

## 1. Prerequisites

| Need | Why | Notes |
|------|-----|-------|
| **Python 3.10+** (3.12 in practice) | The code uses `str \| None` unions; compiled caches are cpython-3.12. | |
| **RabbitMQ** | Job queue between API and worker. | Local default expects `127.0.0.1:5672`, `guest/guest`, vhost `/`. The code falls back to `guest/guest` on localhost if custom creds fail. |
| **SerpWow API key** | The only web-data source (search + maps). | `SERPWOW_API_KEY`. |
| **Google Gemini API key** | LLM for transliteration, URL choice, firmographics, and batch descriptions. | `GEMINI_API_KEY`. |
| **AWS S3 bucket** *(optional)* | Durable artifact storage + cross-process state. | Omit `S3_BUCKET` to run **local-only** under `/tmp/single_ra_isi/`. |

> Local-only mode (no S3) works for a single-host dev setup because the API and worker both write
> to `/tmp/single_ra_isi/`. In a multi-host or container split, you **need** S3 so the two
> processes share state.

## 2. Install dependencies

No lockfile exists; install the imported packages directly:

```bash
python -m venv .venv && source .venv/bin/activate
pip install \
  fastapi uvicorn \
  aio-pika \
  boto3 \
  httpx aiohttp \
  pydantic \
  python-dotenv \
  pyyaml \
  pandas openpyxl     # only needed for convertjtox.py
```

(`aiormq` and `botocore` come transitively with `aio-pika` and `boto3`.)

## 3. Configure

Copy the template and fill in the values that the code actually reads (see
[02.configuration.md](02.configuration.md) — many keys in the template are legacy and ignored):

```bash
cp .env.example .env
```

Minimum:
```ini
SERPWOW_API_KEY=...
GEMINI_API_KEY=...
RABBITMQ_HOST=127.0.0.1
RABBITMQ_PORT=5672
RABBITMQ_USER=guest
RABBITMQ_PASS=guest
RABBITMQ_VHOST=/
# optional S3:
S3_BUCKET=
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
# enable bilingual descriptions:
ENABLE_GEMINI_BATCH_POSTPROCESS=true
```

> Don't leave RabbitMQ/S3 fields as bare `KEY=` (empty). An empty value overrides the code default
> with `""` rather than falling back to it — see the gotcha in
> [02.configuration.md](02.configuration.md).

## 4. Run

### Two-process (recommended / production-like)

```bash
# Terminal 1 — API (producer + Gemini batch driver + UI)
python app.py
#   → uvicorn on API_HOST:API_PORT (code default 0.0.0.0:11500; .env.example uses 14000)
# or:  uvicorn app:app --host 0.0.0.0 --port 14000

# Terminal 2 — worker (consumes jobs, runs the pipeline)
python worker.py
```

The API process is **producer-only** by default; nothing gets processed until `worker.py` runs.

### Single-process (local dev)

Set `ENABLE_EMBEDDED_WORKER=true` and run only `python app.py`. The API process then starts the
RabbitMQ consumers itself at startup, and the stale-row finalizer defaults on.

### Open the UI

`http://localhost:<port>/ui` (e.g. `http://localhost:14000/ui`). FastAPI's interactive API docs
are at `/docs`.

## 5. End-to-end walkthrough (full pipeline)

Using the bundled `smalltest.csv`:

```bash
# 1) Upload (full pipeline)
curl -s -F "file=@smalltest.csv" http://localhost:14000/uploads
#   → {"upload_id":"<UID>", "total_rows":N, "enqueued_rows":N, ...}

# 2) Poll status until rows AND batch are terminal
curl -s http://localhost:14000/uploads/<UID>/status | jq '{status, processed_rows, total_rows, gemini_batch: .gemini_batch.status}'

# 3) Inspect failures (optional)
curl -s "http://localhost:14000/uploads/<UID>/failure-analysis" | jq

# 4) Download results
curl -s "http://localhost:14000/uploads/<UID>/output?download=true" -o result.json
curl -s "http://localhost:14000/uploads/<UID>/output?format=xlsx&download=true" -o result.xlsx
```

Per-pipeline upload endpoints: `/uploads/url-discovery`, `/uploads/firmographics`,
`/uploads/gmaps`, `/uploads/gsearch` (the last also takes a `phase` form field). The firmographics
CSV must have a website column.

Synchronous single lookups (no queue) for quick tests:
```bash
curl -s "http://localhost:14000/crawl?company_name=Acme%20Ltd&country=Bangladesh" | jq
```

## 6. Running the helper scripts

```bash
# Force/repeat the Gemini batch for an upload
python batch_runner.py <upload_id>
python scripts/push_processed_rows_to_gemini_batch.py <upload_id>
#   ⚠ avoid --force-new-job: that path hits app.upload_lock (line 79) which doesn't exist
#     (AttributeError). Without the flag it works. Patch to app.get_upload_lock(upload_id) to use it.

# Recover an upload: requeue stuck rows, wait, then batch only the remaining rows
# ⚠ BROKEN AS-IS: this script references app.upload_lock (line 183), which doesn't exist
#   (app has upload_locks / get_upload_lock). It raises AttributeError after polling the batch,
#   before saving results. Patch line 183 to `async with app.get_upload_lock(upload_id):` first.
python scripts/requeue_wait_and_push_remaining_to_gemini_batch.py <upload_id> [--wait-timeout-sec 1800] [--skip-wait]

# Debug helpers (edit the hard-coded upload_id inside first)
python scripts/debug_state.py
python scripts/debug_s3.py

# One-off: flatten a saved output JSON to Excel
python convertjtox.py            # reads input.json → writes output.xlsx
```

All `scripts/*` and `batch_runner.py` `import app`, so run them from the repo root with the same
venv/`.env`.

## 7. Operational notes & gotchas

- **Worker required.** Uploads sit `queued` forever if no worker (or embedded worker) is running.
- **RabbitMQ down at startup:** `init_rabbitmq` failures are caught; the API still serves, but
  upload creation returns `503` until RabbitMQ is reachable. (No automatic reconnect loop beyond
  `aio_pika`'s robust connection.)
- **Concurrency:** the worker runs `WORKER_CONCURRENCY` consumers and SerpWow calls are globally
  throttled by `SEARCH_FETCH_CONCURRENCY`. Increase both for throughput; mind SerpWow rate limits.
- **Timeouts differ from the template:** code defaults are smaller than `.env.example` for
  `WORKER_JOB_TIMEOUT_SEC` (600 vs 1800), `PROCESSING_STALE_TIMEOUT_SEC` (300 vs 1500),
  `S3_*_TIMEOUT_SEC`, etc. Set them explicitly if you want the template values.
- **State location:** `/tmp/single_ra_isi/<upload_id>/`. On a host where `/tmp` is cleared on
  reboot, only S3 survives — runs without `S3_BUCKET` are ephemeral.
- **Costs:** set `SERPWOW_USD_PER_REQUEST` and the `GEMINI_*_USD_PER_1M_TOKENS` knobs if you want
  the reported `*_cost_usd` fields to reflect your real pricing (defaults are placeholders).
