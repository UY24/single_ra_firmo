# 10 · Data files & artifacts in the repo

The repo root contains sample inputs, a sample output, and several loose export files left over
from real runs. None of these are required to run the service; they're test fixtures and examples.
(`.gitignore` actually excludes root-level `*.csv`, `*.xlsx`, and `input.json` from version
control, so in a fresh clone these may be absent.)

---

## 1. CSV inputs (test company lists)

All use the standard column aliases parsed by `parse_csv_rows` (see [03 §8](03.data-models.md));
**column order doesn't matter** because the parser matches by normalized header name. Row count =
lines − 1 (header).

| File | Rows | Header | Notes |
|------|------|--------|-------|
| `smalltest.csv` | 169 | `company_name,country,input_full_address,input_industry,firm_id` | Mixed-country sample (Poland, Bangladesh, Turkiye, Argentina, …) with addresses. |
| `smalltest1.csv` | 2 | same | Tiny 2-row slice of `smalltest.csv`. |
| `mediumtest.csv` | 23 | same | Mid-size mixed-country sample. |
| `smalltestfailed.csv` | 54 | `company_name,country,input_full_address,firm_id,input_industry` | Rows that failed in a prior run (kept for retry testing). Note the different column order. |
| `poc_1k_sample.csv` | 999 | `company_name,country,input_full_address,firm_id,input_industry` | ~1k Argentine (`AR`) companies, **no addresses** (tests the no-address query branch). |
| `poc1kresidue191.csv` | 191 | same | Residue of the 1k PoC: ~191 Brazilian (`BR`) companies, no addresses. |
| `d6584620-…-3ca06db5b087_googlephases.csv` | 367 | `company_name,country,firm_id` | Argentine companies; minimal columns. Name matches the gsearch-phases upload `d6584620…` (see XLSX below). |

These exercise: the address-present phases (smalltest/mediumtest), the no-address branch
(poc_1k/residue), and minimal inputs (googlephases).

## 2. `input.json` — a sample combined `/output` payload

A real, completed `full`-pipeline output for `upload_id = 3d3b38a5-f56f-4dce-a46f-b792b76e1f60`
(124 rows, all succeeded, Gemini batch `succeeded`, `batch_cost_usd ≈ 0.139`). Its shape is
exactly the [`output.json`](03.data-models.md) schema (§6 there) — top-level upload metadata +
`results[]`, each with `input`, `status`, `output` (the full `CrawlResponse` incl. the `context`
tree). It is the canonical example to consult when you want to see the **real** result/context
keys (it's how §5 of the data-models doc was verified).

`convertjtox.py` reads this file specifically (`INPUT_FILE = "input.json"`).

## 3. XLSX exports

| File | ~Size | Origin |
|------|-------|--------|
| `output.xlsx` | 1.1 MB | Produced by `convertjtox.py` from `input.json` (pandas-flattened, one column per nested key). **Different layout** from the service's own XLSX. |
| `caa8a70f-…-68a1299a60e8.xlsx` | 5.8 MB | A per-upload export downloaded from `GET /uploads/<id>/output?format=xlsx` (named by `upload_id`). Uses the service's hand-rolled column schema ([03 §7](03.data-models.md)). |
| `d6584620-…-3ca06db5b087.xlsx` | 1.6 MB | Same — the upload that the `…_googlephases.csv` belongs to. |
| `fc1c7ff1-…-6f1988e024.xlsx` (full: `fc1c7ff1-0381-42d5-89ae-6fb1f988e024.xlsx`) | 0.9 MB | Same — another per-upload export. |
| `smalltestfailed.csv.xlsx` | 0.8 MB | An XLSX export corresponding to the `smalltestfailed.csv` run. |

**Two distinct XLSX layouts exist in the repo:**
1. **Service export** (`build_upload_output_xlsx_bytes`, downloaded via the API / named by
   upload_id): one fixed `results` sheet with the column list in [03 §7](03.data-models.md).
2. **`convertjtox.py` export** (`output.xlsx`): pandas auto-flatten — one column per flattened JSON
   path (`output_context_final_url_selection_ai_raw_confidence_score`, etc.), lists joined with
   ` | `. Useful for ad-hoc analysis, not the product deliverable format.

## 4. Excel `~$…` lock files

`.gitignore` ignores `~$*.xlsx` (Office temp lock files). If you open an export in Excel you may
see one transiently; it's not a project file.

## 5. What to keep vs. regenerate

| File(s) | Keep? |
|---------|-------|
| `*.csv` test inputs | Keep — handy fixtures for the different code paths. |
| `input.json` | Keep — the reference example of the output schema. |
| `output.xlsx`, `*.xlsx` (upload-id named), `smalltestfailed.csv.xlsx` | Regenerable artifacts; safe to delete. The upload-id-named ones can be re-downloaded from `/uploads/<id>/output?format=xlsx` only while that upload's state still exists locally or in S3. |
| `AI descriptions requirements.pdf` | Keep — the product brief (see [01](01.overview-and-architecture.md)). |

> Reminder: all of these match `.gitignore` patterns, so they are *local* working files rather than
> tracked source. The tracked source of truth is the Python modules + `templates/` + `.env.example`.
