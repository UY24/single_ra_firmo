# 12 · UI tabs → flow → where the LLM (Gemini) sits

Short reference: for each of the 6 UI tabs, what pipeline runs, and exactly where Gemini is used.
`LLM` = Google Gemini. Full detail: [05.pipelines-and-flow.md](05.pipelines-and-flow.md),
[11.handoff.md](11.handoff.md).

---

## Big picture

```
            UI TAB                 ENDPOINT                PIPELINE            LLM USED?
 ┌────────────────────────┐
 │ Upload Console         │ ─POST /uploads────────────→  full          ──→  YES (most)
 │ Firmographics Upload   │ ─POST /uploads/firmographics→ firmographics ──→  YES (1 call)
 │ Google Maps Lookup     │ ─POST /uploads/gmaps────────→ gmaps         ──→  NO
 │ Google Search Phases   │ ─POST /uploads/gsearch──────→ gsearch       ──→  NO
 │ Retry Operations       │ ─POST .../retry-failed-rows─→ (re-runs the upload's own pipeline)
 │ Batch Manager          │ ─GET/POST /batch/jobs*──────→ (manages Gemini batch jobs; runs none)
 └────────────────────────┘

 Common worker path:   queue → worker → SerpWow (search / maps / ai-overview) → [LLM points] → state.json
 Rule of thumb:  SerpWow = get raw data.   Gemini = (a) prep inputs, (b) decide the URL, (c) clean firmographics, (d) write descriptions.
                 Google Maps results are cleaned by PYTHON scoring, never directly by the LLM.
```

---

## 1. Upload Console  → `full` pipeline  →  **LLM: heavy**

```
CSV row
  → transliterate_inputs_with_gemini          [LLM] clean inputs → Latin script
  → classify_address_with_gemini              [LLM] judge address quality
  → parse_city_state_from_full_address…       [LLM] extract city/state for queries
  → SerpWow search ×N        (Python extracts candidate URLs — no LLM)
  → Google Maps via SerpWow  (Python picks best place URL — NO LLM)
  → choose_final_website_with_gemini          [LLM] pick the official URL  *(skipped if batch ON)*
  → SerpWow codetails AI-overview
  → standardize_serpwow_ai_overview_with_gemini[LLM] clean → address/phone/email/industry/products/services  *(skipped if batch ON)*
  ── when all rows done & ENABLE_GEMINI_BATCH_POSTPROCESS=true ──
  → Gemini BATCH                               [LLM] final URL + bilingual ≥250-char descriptions + firmographics, all rows in one call
```
LLM calls per row: **3** input-prep + **1** URL pick + **1** firmographics clean, **then 1 batch** at the end.
With batch ON, the per-row URL-pick + firmographics-clean are **skipped** (batch does them) — so you don't pay twice.

## 2. Firmographics Upload  → `firmographics` pipeline  →  **LLM: 1 call**

```
CSV row already has the URL
  → SerpWow codetails AI-overview for the domain   (get raw data)
  → standardize_serpwow_ai_overview_with_gemini    [LLM] clean → structured firmographic fields
```
No input transliteration, no URL chooser, no batch. The single LLM call just structures the AI-overview.

## 3. Google Maps Lookup  → `gmaps` pipeline + standalone tools  →  **LLM: none**

```
query → SerpWow places (data_cids) → SerpWow place_details
      → _select_best_gmaps_website (PYTHON scoring)  → website + address + phone + category
```
Batch CSV (`/uploads/gmaps`) and the standalone Discover / Full Search / Place-Details tools
(`/gmaps/discover|search|details`) are **100% SerpWow + Python**. Gemini is **never** involved here.

## 4. Google Search Phases  → `gsearch` pipeline + standalone tool  →  **LLM: none**

```
company/country/(address) → build phase queries (phase1..phase5/fallback)
      → SerpWow search ×N → collect unique allowed candidate URLs (PYTHON)
      → return first candidate
```
Diagnostic/experimentation mode. Batch CSV (`/uploads/gsearch`, with a phase selector) and the
standalone runner (`/gsearch/discover`) use **no LLM** — just SerpWow + Python candidate collection.

## 5. Retry Operations  → re-runs the upload's own pipeline  →  **LLM: inherited**

```
POST /uploads/{id}/retry-failed-rows
  → reset failed/queued/processing rows to "queued" → re-publish to the queue
  → (for full uploads) reset gemini_batch = waiting_for_rows
```
The retry tab itself makes **no** LLM calls. Re-queued rows run through whatever pipeline that
upload used — so a `full` retry repeats Upload Console's LLM flow; a `gmaps`/`gsearch` retry uses none.

## 6. Batch Manager  → manages Gemini batch jobs  →  **LLM: manages, doesn't run**

```
GET  /batch/jobs                → list local + remote Gemini batch jobs
POST /batch/jobs/{id}/status    → fetch live job state
POST /batch/jobs/cancel|delete  → cancel / delete a batchGenerateContent job
```
This tab is the control panel for the **Gemini batch jobs** that the `full` (Upload Console)
pipeline spawns. It calls Gemini's batch *management* API (list/status/cancel/delete) but starts
**no new** content generation itself.

### One-line summary per tab

| Tab | Pipeline | LLM used | What the LLM does |
|-----|----------|----------|-------------------|
| Upload Console | `full` | **Yes (most)** | prep inputs → pick URL → clean firmographics → (batch) write bilingual descriptions |
| Firmographics Upload | `firmographics` | **Yes (1)** | clean SerpWow AI-overview into structured fields |
| Google Maps Lookup | `gmaps` | **No** | — (Python scoring) |
| Google Search Phases | `gsearch` | **No** | — (Python candidate collection) |
| Retry Operations | re-run | inherited | whatever the retried pipeline uses |
| Batch Manager | — | manages | lists/cancels/deletes Gemini batch jobs (no generation) |
