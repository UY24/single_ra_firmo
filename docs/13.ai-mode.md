# 13 · AI Mode (scrape.do Google AI Mode + LLM cleanup)

**AI Mode** is a new, **standalone** pipeline added to `website_url_finder`. Given a CSV of
companies, it asks **Google's AI Mode** (via [scrape.do](https://scrape.do)) for each company's
official website, then uses an **LLM** (Gemini or OpenAI) to clean that raw answer into one URL per
company. Results are written under `ai_mode_result/<run_id>/`.

It is implemented in `ai_mode_service.py` (the glue/orchestration layer) plus the vendored
`scrapedo_finder/` package (copied in from the sibling `scrapeDo` project), with 4 endpoints in
`app.py` and one UI tab.

---

## How it differs from the SerpWow pipelines

AI Mode is deliberately **separate** from the `full` / `url_discovery` / `firmographics` / `gmaps` /
`gsearch` pipelines documented in [05.pipelines-and-flow.md](05.pipelines-and-flow.md). It does
**not** share their machinery:

| | SerpWow pipelines | **AI Mode** |
|---|---|---|
| Data source | SerpWow (Google results / AI overview / Maps) | **scrape.do** Google AI Mode |
| Queue | RabbitMQ (one job per row) | **none** — one in-process background task per run |
| State | `state.json` (local + S3) | `status.json` + `report.json` under `ai_mode_result/<run_id>/` |
| Persistence | local `/tmp/single_ra_isi/` **and** S3 | **local disk only** (`ai_mode_result/`, gitignored) |
| LLM | Gemini (per-row + batch) | Gemini **or** OpenAI, env-switchable |
| Output | URL + bilingual descriptions + firmographics | **official website per company** only |
| Concurrency | worker pool (`WORKER_CONCURRENCY`) | **sequential, one batch at a time** (v1) |

There is **no RabbitMQ, no S3, no `state.json`** involvement. AI Mode is self-contained.

## End-to-end flow

```
CSV upload  (POST /uploads/ai-mode  or  UI "AI Mode" tab)
   → prepare_ai_mode_run(): new run_id, write ai_mode_result/<run_id>/input.csv, status.json
   → background task: asyncio.create_task(asyncio.to_thread(run_ai_mode_sync, run_id))
        │  rows split into batches of SCRAPEDO_BATCH_SIZE (default 10)
        │  for each batch (SEQUENTIAL in v1):
        │     Phase 1  one prompt for the whole batch → scrape.do Google AI Mode
        │              GET https://api.scrape.do/plugin/google/search/ai-mode  (prompt in ?q=)
        │              → save raw JSON to raw_scrapedo_response/request_NNN.json
        │     Phase 2  feed that raw response to the LLM (Gemini | OpenAI)
        │              → cleaned official website per company in the batch
        │  (per batch, record scrape.do time + LLM time via time.perf_counter())
        ↓
   write found.csv / notFound.csv / report.json / final_report.json / run.log
   update status.json
```

Poll `GET /uploads/ai-mode/{run_id}/status` until done, then download
`final_report.json` / `found.csv` / `notFound.csv` from the result endpoint.

## Configuration (environment variables)

AI Mode reads the **process environment** (`app.py` has already loaded `.env` at import time — see
[02.configuration.md](02.configuration.md)). It does **not** load any separate scrape.do `.env`.
All keys are read in `ai_mode_service.py` via the local `_int_env` / `_float_env` / `_bool_env` /
`_str_env` helpers, which fall back to the default when the key is absent **or blank**.

### scrape.do (Phase 1)

| Variable | Default | Notes |
|----------|---------|-------|
| `SCRAPEDO_TOKEN` | `""` | **Required.** `Settings.validate()` raises if empty → the run fails. |
| `SCRAPEDO_BATCH_SIZE` | `10` | Companies sent per scrape.do prompt (= one `request_NNN.json`). |
| `SCRAPEDO_TIMEOUT_SECONDS` | `90` | HTTP timeout for the scrape.do call. |
| `SCRAPEDO_MAX_RETRIES` | `2` | scrape.do retry attempts. |
| `SCRAPEDO_MAX_QUERY_CHARS` | `6000` | Cap on the generated `q` prompt length. |
| `SCRAPEDO_DEVICE` | `""` | Optional locale/render knob passed through to scrape.do. |
| `SCRAPEDO_HL` | `""` | Optional UI language. |
| `SCRAPEDO_GL` | `""` | Optional geo/country. |
| `SCRAPEDO_GOOGLE_DOMAIN` | `""` | Optional Google domain. |
| `SCRAPEDO_SAFE` | `""` | Optional SafeSearch setting. |
| `SCRAPEDO_INCLUDE_HTML` | `false` | Whether to ask scrape.do for the rendered HTML too. |

### LLM cleanup (Phase 2)

| Variable | Default | Notes |
|----------|---------|-------|
| `AI_MODE_LLM_PROVIDER` | `gemini` | `gemini` or `openai`. Anything else falls back to `gemini`. |
| `GEMINI_API_KEY` | `None` | **Reused** from the existing config (required when provider = `gemini`). |
| `GEMINI_MODEL` | `gemini-2.5-flash-lite` | **Reused** from the existing config. |
| `OPENAI_API_KEY` | `""` | Required when provider = `openai`. |
| `OPENAI_MODEL` | `gpt-4o-mini` | OpenAI model. |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Override for OpenAI-compatible endpoints. |
| `LLM_MAX_RETRIES` | `2` | LLM retry attempts. |
| `LLM_TIMEOUT_SECONDS` | `120` | LLM HTTP timeout. |

> **Note:** `GEMINI_API_KEY` and `GEMINI_MODEL` are **shared** with the SerpWow pipelines — AI Mode
> reuses them rather than introducing its own. `LLMConfig.validate()` raises (and the run fails) if
> the selected provider's API key is empty.

## Input CSV — auto-detected mode

The mode is detected from the CSV **headers** (no form field needed). Headers are normalized
(lowercased, whitespace → underscores) before matching.

| Mode | Trigger | Columns used |
|------|---------|--------------|
| **Company** | a `Company Name ENG` column is present | `ISIC`, `Country Code`, `Company Name ENG`, `Company Name Local` |
| **Address** | otherwise (default) | name = `entity_name` \| `company_name` \| `company` \| `name`; `country`; address = `address` \| `input_full_address` \| `full_address` |

Because of the address mapping, the **existing `website_url_finder` CSVs**
(`company_name,country,input_full_address,...`) work as-is in **address mode** — no reformatting
needed.

## On-disk layout — `ai_mode_result/<run_id>/`

(`ai_mode_result/` is gitignored, alongside `single_ra_isi/` / `uploads/` / `artifacts/`.)

| Path | Contents |
|------|----------|
| `input.csv` | The uploaded CSV, saved verbatim. |
| `status.json` | Live run status (state, counts, progress) — the heartbeat the status endpoint serves. |
| `report.json` | Intermediate per-batch report. |
| `final_report.json` | Final report: `requests[]` (per batch) + `summary` (totals + `token_usage`). |
| `found.csv` | Companies for which an official website was resolved. |
| `notFound.csv` | Companies with no resolved website. |
| `run.log` | Per-run log. |
| `raw_scrapedo_response/request_NNN.json` | The raw scrape.do JSON, **one file per batch**. |

## Timing fields

Each batch records the **scrape.do response time** and the **LLM cleaning time** separately
(`time.perf_counter()`), surfaced in `final_report.json`.

**Per batch — `final_report.json.requests[]`:**

| Field | Meaning |
|-------|---------|
| `request_index` | Batch number (1-based), matches `request_NNN.json`. |
| `entity_count` | Companies in this batch. |
| `scrapedo_seconds` | Phase 1 (scrape.do) duration. |
| `llm_seconds` | Phase 2 (LLM cleanup) duration. |
| `combined_seconds` | `scrapedo_seconds + llm_seconds` for the batch. |
| `status` | Batch outcome. |
| `error` | Error string, if any. |
| `raw_json_file` | The `raw_scrapedo_response/request_NNN.json` saved for this batch. |

**Totals — `final_report.json.summary`:**

| Field | Meaning |
|-------|---------|
| `scrapedo_seconds_total` | Sum of all `scrapedo_seconds`. |
| `llm_seconds_total` | Sum of all `llm_seconds`. |
| `batch_duration_seconds` | Total wall-clock duration of the run. |
| `token_usage` | Aggregate LLM token usage. |

## HTTP endpoints

All defined in `app.py` (`app.py:7466`–`7516`). Each lazily `import ai_mode_service` and offload
the work via `asyncio.to_thread`.

| Method · Path | L# | Input | Returns |
|---|---|---|---|
| `POST /uploads/ai-mode` | 7466 | `multipart/form-data` field **`file`** (CSV) | Parses + saves the CSV, kicks off the background task, returns the run receipt (`{run_id, ...}`). `400` if the CSV is unusable (`ValueError`). |
| `GET /uploads/ai-mode` | 7480 | — | `{count, runs:[...]}` — all known runs. |
| `GET /uploads/ai-mode/{run_id}/status` | 7487 | — | The run's `status.json`. `404` if `run_id` is unknown. |
| `GET /uploads/ai-mode/{run_id}/result` | 7496 | query `file` (def `final_report.json`), `download` (bool) | Streams the requested result file. `download=true` adds a `Content-Disposition` attachment header (filename `<run_id>_<file>`). |

**Allowed `result` files:** `final_report.json`, `found.csv`, `notFound.csv`, `report.json`,
`run.log`, `input.csv`. Anything else → `400`. `404` if the run is unknown or the file isn't
written yet.

## How to run

1. Set the required env vars in `.env`:
   - `SCRAPEDO_TOKEN=<token>` (always required), **and**
   - `GEMINI_API_KEY=<key>` (default provider), **or** `AI_MODE_LLM_PROVIDER=openai` + `OPENAI_API_KEY=<key>`.
2. Start the API as usual (see [09.how-to-run.md](09.how-to-run.md)) and open `GET /ui`.
3. Go to the **AI Mode** tab and upload a CSV (company-mode or address-mode — auto-detected).
4. Watch progress; when done, download `final_report.json` / `found.csv` / `notFound.csv`.

CLI equivalent:
```
POST /uploads/ai-mode  (file=companies.csv)        → {run_id}
loop:
  GET /uploads/ai-mode/{run_id}/status             → until terminal
GET /uploads/ai-mode/{run_id}/result?file=found.csv&download=true
```

## v1 → v2 boundary

- **v1 (current):** batches run **sequentially** — one batch of `SCRAPEDO_BATCH_SIZE` at a time
  (Phase 1 then Phase 2, then the next batch). Simple and easy to reason about; throughput is
  bounded by per-batch latency × batch count.
- **v2 (planned):** **parallelize batches** (fan out multiple scrape.do + LLM calls concurrently).
  The on-disk layout, report schema, and endpoints are designed to stay the same — only the batch
  scheduling changes.
